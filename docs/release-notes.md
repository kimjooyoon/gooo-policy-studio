Gooo 정책 변경의 자동 검사와 사람이 건별 승인하지 않는 **로컬 기계 실행 게이트**를 포함하는 preview입니다.

- `policy-studio`: 동일한 사례의 변경 전후 정책 비교, 완전한 영향 보고서와 재실행.
- `policy-check`: 다섯 합성 API·자동화 사례의 기대 판단을 검사하는 실행 파일. 일치·불일치·오류를 종료 코드로 구분합니다.
- `policy-gate`: 인증된 주체가 서버 정책과 요청으로 로컬 `pending → approved` 상태를 전이합니다. 정책 version·요청 revision·주체별 idempotency key를 확인하고 승인·거절 결과를 함께 저장합니다. 같은 주체·키·명령의 재시도는 재시작 뒤에도 원래 결과를 반환합니다.

운영체제와 CPU에 맞는 실행 파일, 필요한 예제 JSON, `START-HERE.txt`, `provenance.json`, `SHA256SUMS`를 내려받으세요. 실행에는 Go/Gooo 설치나 모델 서비스가 필요하지 않습니다. Studio와 policy-check는 Linux·macOS·Windows 타깃을 제공하며, gate는 필수 저장 잠금을 지원하는 Linux·macOS 타깃만 제공합니다.

전체 소스 검사 성공 뒤 배포 파일을 만듭니다. 배포할 Linux/amd64 gate 실행 파일의 실제 12개 API 시나리오, policy-check 실행 파일의 다섯 사례 및 보고서 재실행 결과를 함께 제공합니다. 다른 타깃의 교차 컴파일 결과와 실제 실행 근거는 구분합니다. 생성 코드·컴파일러 출처와 모든 자산의 바이트 해시는 별도 근거에 연결합니다.

게이트의 효과는 신뢰하는 로컬 요청 상태 변경 하나입니다. 설정은 로드 시 고정되며 외부 API 호출·구매·송금을 실행하지 않습니다. 저장 결과가 불확실하면 추가 작업을 차단하고 유효한 영속 상태로 복구해야 합니다. 강제 crash·전원 장애·고객 운영은 검증하지 않았습니다. 파일 해시는 내용 일관성 검사이며 발행자를 인증하는 서명이 아닙니다.

먼저 Studio를 실행해 http://127.0.0.1:8080 에 접속하거나, `START-HERE.txt`의 명령으로 정책 검사와 새 기계 게이트 상태를 준비하세요. 기존 `v0.1.0`은 당시의 시뮬레이터 스냅샷으로 유지됩니다.
