# 실제 산출물 검증을 연결한 기계 실행 게이트

`policy-gate`의 v2 구성은 인증된 요청을 판단하기 전에 운영자가 지정한 실제
JSON 파일을 직접 검사합니다. 사람이 요청마다 승인하지 않아도, 명시한 조건을
만족하는 로컬 `pending → approved` 전이만 수행하도록 구성합니다. 이 기능은
현재 소스에서 빌드하며 기존 배포 미리보기 실행 파일에는 포함되지 않습니다.

## 운영자가 정하는 조건

[`bootstrap.json`](../examples/artifact-gate/bootstrap.json)의 스키마는
`policy-studio/admission-bootstrap/v2`입니다. 기존 정책·주체·요청에 `preflight`와
요청별 `artifacts`를 추가합니다. v1은 새 필드를 거절하고 기존 계약을 유지합니다.
기존 v1/v2 상태를 다른 구성이나 실행 출처로 자동 migration하지 않습니다.

- 각 요청에 파일 경로, 예상 SHA-256, 만료 시각 하나를 지정합니다.
- `flat-json/v1` 생산자에 정확한 산출물 스키마와 모든 필드의 타입을 지정합니다.
  `text`, `bool`, `int64`만 지원합니다. 예상 필드의 누락·추가·null·중복·타입
  불일치와 모호한 JSON을 거절합니다. 정수는 정규 십진 int64 형식으로 비교합니다.
- 필수 검증 1~256개에 고유 ID와 `field_equals/v1` 조건을 지정합니다.
  값 비교 이전에 전체 파일 SHA-256·스키마·타입을 반드시 확인합니다.
- 근거의 요구 권위, 관측의 최대 나이, 승인 및 거절 기록의 효과 예산을 지정합니다.
  지원하지 않는 생산자·검증기·권위는 초기화 전에 거절합니다.

일반 API 호출자는 이 설정이나 성공 관측을 제공할 수 없습니다. 기존과 동일한
네 필드 `request_id`, `expected_revision`, `policy_version`, `idempotency_key`만
보냅니다. 인증·실행 권한을 먼저 확인합니다. 새 명령은 현재 정책
version·revision도 확인합니다.
기본 Gooo 정책이 거절하면 파일을 읽지 않고 모든 필수 검증을 `unknown`으로
남깁니다. 인증 실패나 오래된 명령은 새 결과 기록도 만들지 않습니다.

## 실제 바이트에서 Gooo 판단까지

기본 정책이 허용하면 호스트가 파일을 한 번 읽습니다. 각 경로 성분의 symlink,
일반 파일이 아닌 대상, 과대 파일, 읽는 동안 변경된 파일을 거절합니다.
CLI 초기화는 관리자가 선택한 부모 경로를 실제 경로로 한 번 정규화합니다.
런타임 읽기는 그 경로의 symlink를 따라가지 않습니다.

생산자는 보유한 바이트로 모든 필수 조건을 평가합니다. 호스트는 실제 생산자,
요청·주체·정책·산출물 연결, 실제 관측 시각과 현재 시각을 구성합니다.
각 관측을 Gooo `EvidenceAdmission`에 전달하고, 전체 필수 검증을 기존
`completion` 누적 판단에 연결합니다. 최종 Gooo `ArtifactGateAdmits`는 기본 정책, 검증 수,
사용 가능한 근거 수, 완료 여부, 출처 연결 및 두 효과 예산을 함께 판단합니다.
중간 실패가 뒤의 성공으로 지워지거나 필수 목록이 호출자 입력에서 줄어들지 않습니다.

REA의 권위 호환성·도구 효과·완료 집계에서 시작했지만, 실제 산출물·정책·관측을
묶는 흐름은 Gooo에서 새로 구성했습니다. 원본의 MIT 표시를 유지합니다.
Gooo가 만든 Go 함수와 출처를 실행 파일에 포함하므로 실행 시 Gooo 설치,
네트워크, 외부 서비스가 필요하지 않습니다. 언어 엔진은 변경하지 않았습니다.

## 승인과 거절 모두의 효과

승인 효과는 로컬 대상 상태 변경, 세션 변경, 파일 쓰기이며 멱등성을 요구합니다.
거절 기록도 세션 변경과 파일 쓰기이므로 별도 `control_plane_budget`으로 검사합니다.
그 예산이 허용하지 않으면 상태나 자격증명 생성 전에 초기화가 실패합니다.
승인 예산이 대상 변경을 금지하면 요청을 승인하지 않고 허용된 거절 기록만 저장합니다.

두 경로 모두 프로세스 실행·네트워크·UI 변경·자료 폐기·외부 코드 실행·장치 변경을
수행하지 않는 것으로 감사했습니다. 파일 읽기는 별도의 감사 필드 `reads_artifact`로
기록합니다. REA의 효과 분류에는 파일 읽기 권한 항목이 없으므로 그 분류가 자료
접근 정책 전체를 표현한다고 주장하지 않습니다. 운영자는 해당 파일의 접근 권한과
응답 수신자의 자료 접근 권한도 함께 관리해야 합니다.

## 최신성과 저장 경계

실제 파일 읽기 뒤의 호스트 시각으로 근거 나이와 만료를 판단합니다. 승인용
임시 상태를 쓰고 동기화한 뒤 교체 직전에도 현재 시각으로 모든 근거를 다시
검사합니다. 그 사이 만료하면 승인 교체를 하지 않고 거절 결과를 저장합니다.
시각이 뒤로 이동하면 추가 전이를 거절합니다. `max_age_seconds: 0`은 같은 Unix
초에 관측·판단해야 통과하며 만료 시각과 같은 초에는 이미 만료입니다.

보고서의 `decision_unix`는 기록된 판단 시각입니다. 교체 직전 검사나 실제 디스크
저장 순간에 대한 외부 시각 증명을 제공하지 않습니다. 기존과 동일하게 상태와
결과를 하나의 원자적 파일 교체로 저장하고, 저장 결과가 불확실한 I/O 오류에는
해당 프로세스의 추가 실행을 중단합니다. 정상 종료 후 재시작을 실제 프로세스로
검사하며, 주입된 저장 오류 검사는 실제 전원 장애 실험을 뜻하지 않습니다.

같은 인증 주체의 정확히 같은 명령·키는 저장된 결과를 그대로 반환합니다.
과거 판단에 사용한 바이트를 보유하므로 파일이 변경되거나 사라진 뒤에도 재시작 시
전체 관측·Gooo 결과·완료·효과·이력을 재계산합니다. 과거 승인이 시간이 지나
재현된 것은 현재 시각에서 새 실행을 허용했다는 뜻이 아닙니다.

## 실행 예제

예제는 내보내기 계획의 형식과 값만 검사합니다. 실제 데이터를 내보내지 않습니다.
만료 시각은 데모용 2100년 값이므로 실제 도입에는 별도 만료 정책이 필요합니다.

```sh
go build -trimpath -o bin/policy-gate ./cmd/policy-gate
mkdir -m 700 -p "$HOME/.local/state/gooo-policy-studio"
./bin/policy-gate \
  -init examples/artifact-gate/bootstrap.json \
  -state "$HOME/.local/state/gooo-policy-studio/artifact-demo" \
  -token-file "$HOME/.local/state/gooo-policy-studio/artifact-demo.token"
./bin/policy-gate \
  -state "$HOME/.local/state/gooo-policy-studio/artifact-demo" \
  -addr 127.0.0.1:8091
```

새 상태 경로와 새 자격증명 파일을 사용합니다. 토큰은 0600 파일에 보관하며
터미널에 출력하지 않습니다. [기계 API 계약](machine-gate.md#api-계약)의 Bearer
인증을 사용하고 `GET /api/state`의 실제 version·revision으로 명령을 구성합니다.
승인 `200`, Gooo 거절과 영속 결과 `403 policy_denied`, 같은 키의 변경 명령이나
오래된 상태 `409`, 불확실한 저장·상한·실행 오류 `503`의 의미는 기존과 같습니다.

## 범위와 검증 근거

파일 최대 64 KiB, 스키마 외 필드 최대 255개, 필수 검증 최대 256개, 초기 요청
최대 256개, 영속 결과 최대 256개, v2 snapshot 최대 64 MiB입니다. 실제 직렬화
바이트가 상한을 넘으면 새 상태를 쓰기 전에 거절합니다. 과거 결과를 자동 삭제해
빈자리를 만들지 않으며 동일 명령의 과거 재시도는 계속 가능합니다. v1의 4 MiB
snapshot 상한은 유지합니다. 초기 JSON은 기존의 1 MiB 상한을 사용합니다.

현재 구현은 Linux·macOS의 지원하는 로컬 파일 시스템에 한정됩니다. 보유한
산출물 바이트와 값은 승인·거절 응답 및 상태에 포함될 수 있습니다. 상태, 토큰,
파일 및 결과의 접근 권한은 관리자가 보호해야 합니다. 출처 해시는 내용 연결을
확인하며 서명이나 외부 발행자의 인증을 제공하지 않습니다. 내장 생산자를 인증된
호스트 경로로 호출하는 범위만 확인하고 임의 외부 보고서는 받아들이지 않습니다.

정해진 파일 조건이 통과했다는 사실은 현실의 모든 위험을 검증했다는 뜻이 아닙니다.
외부 API의 정확히 한 번 실행·송금·조직 전체 예산·임의 정책의 완전성·AI 모델의
보편적 안전성·고객 업무 무인 운영을 보장하지 않습니다. 실제 고객 도입 사례는 없습니다.

[`verify-artifact-gate.py`](../tools/verify-artifact-gate.py)는 실제 실행 파일과
새 자격증명으로 파일 성공·실패·형식·크기·만료, 호출자 override, 재시도, 동시 요청,
정상 종료 후 재시작 및 효과 예산을 검사하고 전체 실제 응답을 보존합니다.
호스트 테스트는 가변 검증 1/5/256개, 시각 경계, 원문 변경, 소유권, 저장 용량과
주입된 I/O 오류를 따로 검사합니다. 최종 Gooo 관계는 31개 별도 유한 기대값과
전체 타입 필드의 실행·재실행 및 변조 거절로 확인합니다. 커밋별 결과와 새 근거는
[Verify Actions](https://github.com/kimjooyoon/gooo-policy-studio/actions/workflows/ci.yml)에서 확인합니다.
